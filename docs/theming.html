LookCalendar has no palette of its own — every value in look-calendar.css resolves through LookUI's own --lk-* tokens. Theme LookUI once; LookCalendar follows.

Try it — live token playground

These controls edit real CSS custom properties on :root — nothing is faked.

Drag across a few days to see the selection color; today's date number uses the today color.

CSS

:root {
  --lkc-header-color: #757575;    /* weekday row / day-header text */
  --lkc-date-color: #1a1a2e;      /* date numbers (month view) */
  --lkc-time-color: #757575;      /* hour labels (week/day view) */
  --lkc-event-color: #5c6bc0;     /* default event color (an event/calendar color always wins) */
  --lkc-today-accent: #5c6bc0;    /* today's filled date circle / highlighted header text */
  --lkc-selection-border: #5c6bc0; /* drag-to-create preview border */
  --lkc-selection-bg: color-mix(in srgb, #5c6bc0 14%, transparent); /* drag-to-create preview fill */
}

Try it — marking days with a color (no event required)

markedDays colors specific days independent of any event — weekends, public holidays, blackout dates. A marked day with no events of its own still shows up (with an otherwise-empty group) in agenda view, instead of silently disappearing.

JavaScript

lkCalendar('#calendar', {
  markedDays: [
    { weekday: [0, 6], color: '#eceff1', label: 'Weekend' },
    { date: '08-17', color: '#ef9a9a', label: 'Independence Day' }, // every year
    { from: '2026-12-24', to: '2026-12-26', color: '#8d6e63', label: 'Office closed' },
  ],
});

// Change the rules on an already-mounted calendar:
calendar.setMarkedDays([{ weekday: [0, 6], color: '#eceff1' }]);
Rule shapeMatches
'YYYY-MM-DD'one specific day (default color)

{ date: 'YYYY-MM-DD', color, label? }one specific day

{ weekday: number[], color, label? }0 (Sun)…6 (Sat), every week

Per-event color — coloring by calendar, automatic

Every event resolves to an effective color, in priority order: its own event.color if you set one; otherwise its calendar's color (calendars: [{ id, name, color }]); otherwise — since autoColor defaults to true — a stable, deterministic color hashed from the event's id, picked from a small built-in palette, so uncolored events still look visually distinct from each other instead of all collapsing onto one color; or, with autoColor: false, the CSS default (--lkc-event-color, i.e. --lk-primary). This is resolved by calendarStore itself — every read (add, update, get, all, between, including expanded recurring instances) returns the effective color, so you never have to look it up yourself. Try it live on the Overview page's color picker.

JavaScript

const store = createCalendarStore({
  calendars: [
    { id: 'work', name: 'Work', color: '#5c6bc0' },
    { id: 'personal', name: 'Personal', color: '#00bcd4' },
  ],
  // autoColor: true is the default — pass false to go back to everything
  // uncolored sharing the single CSS default instead.
});

store.add({ calendarId: 'work', title: 'Standup', start, end });
// -> event.color === '#5c6bc0' (inherited from the "work" calendar)

store.add({ calendarId: 'work', title: 'Urgent fix', color: '#c62828', start, end });
// -> event.color === '#c62828' (explicit color always wins)

store.add({ title: 'Quick note', start, end }); // no calendarId, no color
// -> event.color === one of a dozen built-in hues, picked from this event's own id —
//    the SAME color every time this exact event is read again

// Recolor a whole calendar at once — every event in it updates immediately:
store.setCalendars([{ id: 'work', name: 'Work', color: '#ff9800' }]);

// Recolor one event directly — an explicit color always overrides auto/calendar color:
store.update(event.id, { color: '#ab47bc' });
